# 벤치마킹 — 오픈소스 생태계에는 무엇이 있나 (2026-08-06)

프로젝트를 접기 전, "우리가 놓친 접근법이 있나"를 확인하려고 GitHub 을 훑었다.
검색 축: 알고리즘 트레이딩(★2000+), 퀀트 리서치·백테스팅(★1000+), Lopez de Prado 구현체,
pysystemtrade, freqtrade.

결론부터: **놓친 전략은 없었다. 놓친 건 자산군 다각화이고, 그건 계좌 제약이라 우리가 풀 수 없다.**

---

## 생태계는 네 종류다

### A. 실행 엔진 — 가장 많고, 우리에게 가장 덜 필요했다

QuantConnect/Lean · zipline · backtrader · pyalgotrade · rqalpha · StockSharp · pybroker ·
freqtrade · Superalgos · catalyst.

이들이 제공하는 것은 데이터 파이프라인, 주문 라우팅, 브로커 연동, 이벤트 루프다.
전부 **"어떻게 실행할까"** 계층이고, **"이게 진짜인가"** 계층은 비어 있다.

주목할 점: zipline(Quantopian)·pyalgotrade·catalyst 는 유지보수가 끊겼다.
Quantopian 은 2020년에 폐업했다 — 크라우드소싱 알파의 가장 큰 실험이 상업적으로 실패했다.

우리에게 이 계층은 없다. 다만 **우리 병목은 실행이 아니라 엣지였으므로** 만들 이유가 없었다.

### B. 과최적화 방어 도구 — 우리가 독립 구현한 것과 같은 계열

Lopez de Prado 『Advances in Financial Machine Learning』 구현체가 수십 개 있고,
`stonks/stats.py` 에 우리가 넣은 것과 같은 도구를 담고 있다: DSR, PBO/CSCV, MinBTL, haircut.

**결정적 차이는 강제성이다.**

| | 생태계 | STONKS-03 |
|---|---|---|
| 형태 | 호출 가능한 **함수** | 통과해야 하는 **관문** |
| 안 쓰면 | 그냥 안 쓰인다 | `evaluate()` 를 우회해야만 가능(실제로 한 번 그랬고, 원장 감사로 잡혔다) |
| 시도 수 | 사람이 인자로 적는다 | 원장이 자동 기록, 사람이 못 줄인다 |
| 룩어헤드 | 개발자 주의사항 | 필수 위치인자 — 빼면 타입 에러 |

함수는 결과가 마음에 안 들 때 안 부르면 그만이다. 그게 이 계층이 널리 구현돼 있는데도
아무도 못 이기는 이유라고 본다.

### C. 전략 모음 — 여기가 가장 중요한 발견

freqtrade 공식 전략 저장소(freqtrade 본체 ★44k)를 확인했다. README 요지:

- 전략은 **있는 그대로 제공**되며 보증이 없다
- 대부분 **바로 쓰는 물건이 아니라 출발점**으로 삼으라고 명시
- 일부는 **특정 시장 국면에서만** 작동한다고 명시
- 각 전략의 구성 요소 목록에 **매수 신호 = Hyperopt 결과**라고 적혀 있다

마지막 항목이 핵심이다. **옵티마이저 출력물** — 우리 관문이 정확히 기각하도록 만들어진 물건이다.
그리고 **저장소 전체에 성과 수치가 하나도 없다.**

### D. 실계좌 시스템 — 단 하나 찾았다

**pysystemtrade** (Rob Carver, 前 AHL 포트폴리오 매니저). 2015년부터 자기 돈으로 돌리는
선물 자동매매 시스템, Interactive Brokers 연동. 2024년 유지보수자 인계, 2026년 조직 이관 —
**10년 넘게 살아 있는 유일한 사례.**

그런데 이 README 도 수익률을 쓰지 않는다. 오히려 레버리지 거래로 전액을 잃고 더 빚질 수 있다고
명시하고, 수익 보장이 없다고 못 박는다.

## 벤치마킹의 결론

**가장 신뢰도 높은 두 프로젝트가 둘 다 수익률을 공표하지 않는다.**
검증된 엣지를 공개한 저장소는 찾지 못했다. 애초에 공개되면 차익거래되어 엣지가 아니게 된다.

→ 그렇다면 **우리의 "관문 통과 0건" 은 이 생태계에서 이상치가 아니라 정상값이다.**
차이는 하나뿐이다: 다른 곳은 안 재고, 우리는 재서 숫자로 남겼다.

---

## 베낄 것 — 실제 개선안 3가지

### 1. 다각화가 수익원이다 (pysystemtrade) — **1순위, 그러나 계좌 제약으로 봉쇄**

Carver 시스템의 수익원은 영리한 신호가 아니다. **수십 개 선물(주가지수·채권·통화·상품)을
낮은 상관으로 묶는 것**이다. 같은 신호라도 상관 낮은 자산에 분산하면 변동성이 내려가고,
그만큼 레버리지로 되돌려 같은 위험에서 더 높은 수익을 만든다.

우리가 SPY 단일 자산에서 Sharpe 0.71 에 막힌 이유가 정확히 여기다. 신호를 더 찾을 게 아니라
**상관 낮은 자산을 더 붙였어야 했다.**

**막힘**: 토스는 선물·옵션·공매도 미지원. 미국주식 롱온리만으로는 전부 같은 베타라서
다각화가 성립하지 않는다. 이건 리서치 실패가 아니라 실행 수단의 한계다.

### 2. PBO(과최적화 확률)를 상시 산출물로

`stats.py` 에 `pbo_cscv` 를 구현해뒀지만 관문 판정에는 쓰지 않는다.
Lopez de Prado 계열 저장소들은 이걸 주요 보고 지표로 낸다. 관문에 넣진 않더라도
검정 보고서에 항상 찍히게 하는 편이 낫다.

### 3. 데이터 계층을 분리하고 조정(adjustment)을 그 안에 가둔다

zipline·Lean 은 배당·분할 조정을 **데이터 계층의 책임**으로 못박는다.
우리 토스 배당 누락 사고 — 전략 코드가 원시 가격을 그대로 받아 써서 모든 절대수익이
1~2%p 낮게 나온 일 — 는 정확히 이 계층이 없어서 생겼다.

## 베끼면 안 되는 것

**Hyperopt / 유전 알고리즘 파라미터 최적화** (freqtrade 의 간판 기능).

우리 원장 기준으로 hyperopt 1회 = 시도 수천 건이다. DSR 문턱이 천장을 뚫는다.
204건만으로도 이미 자기파괴를 겪었다 — 알파 30%짜리 신호조차 통과할 수 없게 됐다.

이 생태계에서 가장 인기 있는 기능이, 우리 관문 기준으로는 **엣지를 파괴하는 도구**다.
둘 중 하나는 틀렸고, 어느 쪽이 틀렸는지는 freqtrade 전략집에 성과 수치가 없다는 사실이 말해준다.
