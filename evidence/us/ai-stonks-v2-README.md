# AI-STONKS v2 — 초단기 단타 재구성 (보안·리스크 우선)

기존 `AI_STONKS`(라이브·전략동결)를 **초단기/데일리 매매**로 새로 짜는 재구성 프로젝트.
철학: **보안·리스크가 1번, 전략·수익은 그다음.** 그래서 전략보다 **리스크 게이트/킬스위치를
먼저** 만들고, 기본은 **페이퍼(dry-run)** 로만 돈다.

> ⚠️ 현재 단계 = **안전 기반(foundation)만**. 실브로커 연결·전략·실주문은 아직 없다.
> 기존 라이브 `AI_STONKS`는 **건드리지 않는다**(신버전이 검증될 때까지 그대로 운영).

## 왜 이렇게(설계 원칙)
1. **모든 주문은 `RiskGovernor` 를 통과**해야 한다. 하드 리밋을 넘으면 거부.
2. **기본은 페이퍼.** 실주문은 **이중 게이트**(`dry_run=False` + `confirm_live=True`)일 때만.
3. **불확실하면 거부(fail-closed)** — 마크가 미확인·검사 오류·잘못된 입력은 전부 DENY.
4. **킬스위치 하나로 전면 정지** — `HALT` 파일이 있으면 어떤 주문도 안 나간다.

## 킬스위치 & 페이퍼 데몬
```
python -m ai_stonks_v2.killswitch on|off|status   # HALT 파일 = 전면 정지
python -m ai_stonks_v2.daemon --date 2026-07-10 --universe legacy   # 하루치 페이퍼 실행
```
**페이퍼 데몬**("손 놓고 자동"의 뼈대, 실제 돈 0): 거래일 확인(미장 캘린더) → 급등주 세션 →
ORB → RiskGovernor 관통 → PaperBroker 체결 → SQLite 저널 → 일일 텍스트 리포트.
HALT 파일이 있으면 데몬도 즉시 정지(실전과 동일 규칙). schtasks 로 장 마감 후 1회 호출 상정.
전략 관문(inplay 통계)을 통과하기 전까지 **페이퍼 전용** — 실브로커만 갈아끼우면 실전 경로.

## 전략 정체성 (2026-07-09 확정): 급등주 단타 = "Stocks in Play" ORB
사용자 방향 = 급등주 단타/스캘핑. 리서치 결론:
- **틱 스캘핑(목표 0.1~0.2%)은 개인 수수료에선 수학적으로 불가능** — `python -m ai_stonks_v2.costs` 표 참고 (필요승률 w\*=(s+c)/(g+s) > 100%).
- 대신 **ORB(개장 레인지 돌파) × 급등주(Stocks in Play)** 는 학계 검증 사례 존재: Zarattini & Aziz(SSRN [4416622](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=4416622)·[4729284](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=4729284)) — 5분 ORB, 수수료 차감 후 연 33~36% 알파 보고(2016-2023). 단, **남의 백테스트는 가설일 뿐** — 우리 데이터·우리 비용으로 재검증 전엔 실전 금지.
- 개인 단타 기본율은 잔혹: 브라질 선물 데이트레이더 97% 손실, 대만 <1%만 지속 수익. **엣지는 규율(리스크 게이트)+검증에서만 나온다.**

## 테스트 & 백테스트 & 리서치
```
python -m pytest -q               # 45개: 하드리밋/백테스터/검증/ORB·비용/피드·스크리너
python -m ai_stonks_v2.backtest   # 합성 데이터로 전략 비교(수익률/MDD/Sharpe/승률)
python -m ai_stonks_v2.costs      # 스캘핑 손익분기 필요승률 표(비용 현실)
python -m ai_stonks_v2.research QQQ   # 실데이터(yfinance 5분봉) ORB 백테스트 + 순열검정/워크포워드
```

**실데이터 결과 로그 (음의 결과도 기록한다 — 그게 관문의 존재 이유):**

| # | 실험 (5분봉; 1~5=yf 60일, 6~8=polygon 2년) | 거래 | 평균/건 | t | 판정 |
|---|---|---|---|---|---|
| 1 | QQQ 단독 ORB | 48 | -9.8% 총 | p=0.60 | 금지 |
| 2 | 수동 20종목 × RVOL≥1.5 | 36 | **+36.9bp** | +0.64 | 금지 |
| 3 | **S&P500 기계식** × RVOL≥1.5 | 153 | **-25.5bp** | -1.38 | 금지 |
| 4 | S&P500 기계식 × RVOL≥3.0 | 42 | -40.7bp | -0.94 | 금지 |
| 5 | S&P500 기계식 · 롱/숏+ATR (60일) | 366 | -9.6bp | -0.98 | 금지 |
| 6 | legacy(수동) · **polygon 2년** · 롱/숏 | 2778 | +62.6bp | +7.66 | ⚠️생존편향 |
| 7 | **S&P500 기계식 · polygon 2년** · 롱/숏 | 3822 | +14.0bp | +2.89 | ⚠️룩어헤드 |
| 8 | **#7 + 룩어헤드 제거**(개장상대거래량) 5bp | 15217 | **−22.2bp** | **−15.96** | 금지(결정) |
| 8b | #8 + 슬리피지 10 / 15bp | 15879 | −32.3 / −42.3bp | −24 / −31 | 금지 |

**🏁 최종 결론(#7 vs #8 — 이 프로젝트의 핵심 발견):** #7의 +14.0bp는 **룩어헤드 편향**이었다. in-play 판정에 *그날 전체 거래량*(장 마감 후에나 아는 값)을 썼기 때문. 진입 시점(개장 30분)에 **실제로 아는 정보(개장 상대거래량)**로만 종목을 고르자 결과가 **+14.0bp → −22.2bp로 뒤집혔다**(t=−15.96, 부트스트랩 CI[−250,−194], 1.5만 거래). 슬리피지를 10→15bp로 올리면 −32→−42bp. **즉, 실시간에 실제로 돌릴 수 있는 형태로는 급등주 ORB가 대형주에서 압도적으로 손실이다.** legacy +62.6bp(생존편향) → sp500 +14.0bp(룩어헤드) → **−22.2bp(진실)**. 다섯 겹의 가짜 엣지를 벗겨내 도달한 결론이며, **이 형태의 급등주 ORB는 개인에게 엣지가 없다(실전 영구 금지).** 잔여 후보는 전시장 소형주뿐이나 거긴 스프레드가 커 슬리피지가 30~50bp → 사실상 사망. **파라미터를 만져 관문을 억지 통과시키는 것은 p-해킹이므로 하지 않는다.**

**소형주 확인(07-12):** S&P600 소형주·룩어헤드제거·롱숏에서 −47.6bp(15bp)/−77.6bp(30bp)/−117.6bp(50bp), t=−28~−69. **소형주가 더 나쁨**(스프레드↑=비용↑). 전략 서베이(gap-fade·reversal·vwap·last-hour·overnight) 7종도 전부 기각. **인트라데이 전 방식이 비용(고회전)에 사망.** 다음 검증 = 저회전(일봉 스윙) — 비용 드래그가 1/10~1/50이라 유일한 생존 후보.

### 팩터 서베이 (07-30): Alpha101 34개 × 150종목 × 20년

사람이 상상한 전략을 하나씩 검정하는 방식에서, **논문 신호 다발을 기계가 돌리고 방어가 걸러내는**
구조로 전환. 신호 정의만 Kakushadze(2015)에서 가져오고 검증은 우리 관문이 한다.

| 보유기간 | 회전율 | 최고 순Sharpe | 최고 팩터 | DSR | 판정 |
|---|---|---|---|---|---|
| 1일 | 50~80% | −0.37 | alpha019 | 0.000 | 기각 |
| 5일 | 11~18% | +0.10 | alpha049 | 0.006 | 기각 |
| 21일 | 3~4% | **+0.48** | alpha020 | 0.287 | 기각 |
| 63일 | 1% | +0.46 | alpha015 | 0.647 | 기각 |

**신호는 실재한다 — IC 최대 +0.0162(ICIR +1.6), 총Sharpe(무비용) +0.6~+1.4.** IC 0.016은
qlib 벤치마크 최고(0.05)보다 작아 규모도 현실적이다. 그런데 **1일 보유에선 회전율 50~80%가
알파를 통째로 먹어치운다**(순Sharpe 전부 음수) — 인트라데이 전멸과 동일한 사망 원인.

**보유기간을 늘리면 비용 문제는 실제로 해결된다**(회전율 80%→1%, 순SR −3.5→+0.48). 그런데:
1. **최고 팩터가 보유기간마다 바뀐다** (1일 alpha019 → 21일 alpha020 → 63일 alpha015).
   진짜 엣지라면 차원을 옮겨도 같은 팩터가 이겨야 한다. 승자가 흔들리는 것 = 노이즈를 고르는 중.
2. **DSR 최대 0.647 < 0.95** — 34개 중 최고를 골랐다는 사실을 반영하면 유의성이 사라진다.
   더구나 이 DSR은 보유기간별로 35개 시도만 센 값이고, 정직한 시도 수는 34×4=136이므로
   **실제 DSR은 이보다 더 낮다.**
3. 최고치 +0.48조차 20년 S&P500 buy&hold Sharpe(≈0.5~0.6)를 **못 넘는다**.

**결론: 정직하게 비용을 매긴 Alpha101은 미국 대형주에서 생존하지 못한다(136개 구성 전부 기각).**
가격·거래량만 쓰는 신호는 계산이 가장 싸서 가장 먼저 차익거래된다는 가설과 일치.

**핵심 교훈(#2 vs #3): 유니버스를 손으로 고르자 +36.9bp, 기계식으로 바꾸자 -25.5bp — #2의 '엣지'는 상당 부분 생존편향(사후확신)이었다.** #5에서 **숏 사이드 + ATR 스탑**을 붙이자 t가 -1.38→-0.98로 개선되고 손실도 완화(-25.5→-9.6bp)됐지만 **여전히 관문 미달**. 결론: 대형주(S&P500)·60일 데이터에선 **롱/숏·ATR을 다 갖춰도 ORB가 비용을 못 넘는다**(효율적으로 차익거래됨). 논문 알파의 잔여 후보 = **전시장 소형주 + 수년 표본**뿐. 이제 프레임워크는 논문 셋업(롱/숏·ATR)을 충실히 재현하므로, 남은 건 **데이터**다 → Polygon(무료 2년 분봉) 재검정, POLYGON_API_KEY 필요(`feed_polygon.py` 준비 완료).
초기 결과(합성 데이터, 솔직히): **buy&hold(+10%)가 sma-cross(+0.6%)·mean-reversion(-2.1%)를
비용 차감 후 이긴다.** "액티브 단타가 비용을 넘어 알파를 내는가"를 **실데이터로 증명**하기 전엔
실전에 올리지 않는다 — 백테스터가 그 관문.
