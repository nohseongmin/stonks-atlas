# dumpItAll

> **$100 으로 코인 무기한선물 레버리지 단타가 되는가.**
> 전략을 짜기 전에 산술로 먼저 답한다.

```bash
python -m dump.costs      # 비용 산술 — 이 프로젝트의 첫 관문
pytest -q                 # 29 tests
```

---

## 왜 순서를 뒤집었나

앞선 두 프로젝트가 **똑같은 자리에서 죽었다.**

| 프로젝트 | 규모 | 결과 | 사인 |
|---|---|---|---|
| **STONKS-03** | 480 시행 · 3 시장 | 관문 통과 **0** | 인트라데이 전멸 — 신호가 아니라 회전율 |
| **AI_STONKS v2** | 급등주 ORB · 폴리곤 2 년 | **−22.2bp, t = −15.96** | 생존편향·룩어헤드 5 겹 벗기니 남은 게 없었다 |

두 번 다 **코드를 짜기 전에 산술로 끝났어야** 했다.
`AI_STONKS` 의 `costs.py` 는 실제로 틱 스캘핑을 계산만으로 기각했다 —
개인 수수료에서 필요 승률이 100% 를 넘었다. 그게 이 저장소의 출발점이다.

**그래서 여기서는 비용이 먼저고 전략이 나중이다.**
`python -m dump.costs` 를 통과 못 하는 아이디어는 코딩하지 않는다.

## 이미 확정된 것 — 산술 3 법칙

### ① 손익분기는 레버리지로 안 낮아진다

```
필요 가격변동 = 2f + s          (f = 편도 수수료, s = 스프레드)
```

레버리지는 **수익과 수수료를 똑같이** 배로 만든다. 왕복 11bp 를 넘어야 하는 건
1 배든 50 배든 같다. *"레버리지를 걸면 작은 움직임도 먹을 수 있다"는 착각이 여기서 죽는다.*

### ② 레버리지가 바꾸는 건 **파산 속도**다

```
자본 대비 왕복 비용 = L × (2f + s)
```

| L | 명목 | 자본대비 왕복 | 청산 변동 | 펀딩만 연 | **엣지 0 일 때 −99%** |
|---:|---:|---:|---:|---:|---:|
| 1 | $100 | 0.11% | −99.5% | 2.7% | 418 일 |
| 5 | $500 | 0.55% | −19.5% | 13.7% | 84 일 |
| **10** | $1,000 | **1.10%** | **−9.5%** | **27.5%** | **42 일** |
| 20 | $2,000 | 2.20% | −4.5% | 55.0% | 21 일 |
| 50 | $5,000 | 5.50% | −1.5% | 137% | **8 일** |

<sub>왕복 10 회/일 기준. 펀딩은 롱 기준 최근 180 일 실측(BTC 연 2.75%).</sub>

**신호가 정확히 0 이어도** 이 속도로 죽는다. 신호가 나쁘면 더 빠르다.

그리고 청산은 **언제나 전액 손실**이다. 청산수수료가 명목의 **1.25%** —
테이커 체결 25 회분이고 유지증거금(0.40%)의 3.1 배다. L=10 이면 수수료만
자본의 12.5% 인데 그 시점에 남은 증거금은 4% 뿐이다.

> 비용 모델에서 **5bp 를 다듬는 것보다 청산 한 번을 피하는 게 비교가 안 되게 크다.**

### ③ 필요 승률이 스캘핑을 죽인다

```
익절 = 손절 = m 일 때,   p = 0.5 + (2f + s) / (2m)
```

| 목표폭 | 필요 승률 |
|---:|---:|
| 10bp | **105% — 불가능** |
| 20bp | 77.5% |
| 50bp | 61.0% |
| 100bp | 55.5% |
| 500bp | 51.1% |

목표폭이 왕복비용(11bp)과 같아지는 순간 필요 승률이 **100%** 다.
**"작게 자주 먹는다"가 산술적으로 불가능해지는 지점이 여기다.**

### ④ 수익 상한은 레버리지로 못 넘는다 *(STONKS-03 에서 넘어온 항등식)*

```
CAGR − rf = S·σ − σ²/2        σ = S 에서 최대,  그 값이 S²/2
```

Sharpe 1.0 이면 **어떤 레버리지를 써도 연 54% 가 천장**이다.

## 한국에서 되는가 — 회색

> 공개 자료 정리이고 **법률 자문이 아니다.**

**실무: 된다.** 한국 신분증 KYC 로 바이낸스 무기한 150 배까지. 선물은 안 막힌다.
막힌 건 한국 **주식** 무기한 하나뿐이고 그것도 바이낸스 자체 결정이다.

**법: 개인은 범죄가 아니다.** 특금법 §7 은 **미신고 영업자**를 처벌한다.
이용자 처벌 조항은 없다. 단 **레퍼럴·홍보는 방조**로 형사 노출이 된다.
암호화폐 파생은 금지가 아니라 **입법 공백**이다(자본시장법상 기초자산이 아니다).

**그러나 상대방은 FSC 표현 그대로 불법이다.** 보호도 구제도 0.

**자금 출납: 된다.** 업비트·빗썸·코인원 모두 바이낸스를 '계정주 확인' 채널로
정식 지원한다(업비트 목록 기준일 2026-08-27). 바이낸스는 업비트가 전면 차단하는
**미신고 44 곳에 없다**. 조건은 사실상 하나 — **같은 사람 이름**
(성명 + 생년월일 일치, **바이낸스 Middle Name 필드는 비울 것**).

**왕복 마찰 1.77%** (150,000 원 기준, 싼 경로). 흔히 추천되는 TRON 경로는
3.12% 다 — Kaia 가 **75 배 싸고** 업비트가 받는다. 진짜 비용은 시간이다:
최초 원화 입금 후 **72 시간**, 이후 매 입금마다 24 시간 코인 출금이 잠긴다.

> 이 프로젝트 최고 전략(LTW L=14)이 월 약 1.75% 였다.
> **입출금 한 번이 최고 전략의 한 달치를 먹는다.**

위험등급제(LOW/MEDIUM/HIGH)는 **아직 시행 전이다** — 2027-02 경.
현행 운영이 이미 실질 MEDIUM(동일인 명의만)이고, 그때 바이낸스가
저위험이면 완화, 고위험이면 차단된다.

자세히 → [`RECON.md`](RECON.md#5-한국에서-되는가--회색이다-두-쪽이-반대-방향을-가리킨다)

```
dump/feed.py       바이낸스 공개 덤프 + 시점정합 유니버스
dump/backtest.py   체결 시뮬 — 수수료·스프레드·펀딩·청산 전부 계상
dump/gate.py       관문 7종 + 시행 원장. 결과를 보고 문턱을 고치지 않는다
tests/             주장 하나마다 검정 하나 (58 tests)
RECON.md           검증된 숫자만. 출처 없으면 안 들어온다
```

### 관문 7종 — 하나라도 실패하면 기각

| | 검사 | 문턱 |
|---|---|---|
| ① | **시점정합** | 상폐 종목 포함 유니버스를 썼는가 |
| ② | 표본길이 | 365 기간 이상 |
| ③ | **청산** | 0 회. 낙폭과 다른 종류의 사건이다 |
| ④ | 벤치대비 | BTC 매수보유 대비 Sharpe 여유 +0.20 |
| ⑤ | **비용스트레스** | 가정 비용 **3 배**에서도 벤치 초과 |
| ⑥ | 낙폭 | 50% 이내 |
| ⑦ | **잡음바닥** | 시행 n 건이 운으로 낼 최댓값을 넘는가 |

관문 자체에도 검정력 테스트가 붙어 있다 — **진짜 좋은 전략을 통과시키는지** 확인한다.
전부 기각하는 관문은 정보가 없다.

### 백테스터가 막는 것

| 함정 | 어떻게 막나 |
|---|---|
| **룩어헤드** | `PastView` 가 `t` 이후 인덱스에 `IndexError`. 새려고 하면 터진다 |
| **청산 누락** | 봉 안 고가/저가로 판정. 종가만 보면 절대 안 잡힌다 |
| **유지 vs 청산 혼동** | `None`(유지)과 `0`(청산)을 구분. 섞으면 위험 축소가 작동 안 한다 |
| **갭 소실** | `close[t] → open[t+1]` 을 체결 전에 먼저 정산 |
| **체결 낙관** | `t` 봉 종가로 판단, `t+1` 시가 체결. 첫 봉 수익은 구조적으로 못 먹는다 |

*마지막 두 개는 테스트가 잡았다. 처음 구현은 갭을 통째로 버렸다.*
