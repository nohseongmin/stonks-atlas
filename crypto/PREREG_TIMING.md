# 사전등록 — #8 타이밍 (단일자산 진입·청산)

**작성 시각: 하나도 돌리기 전.**

## 왜

**123 시행이 전부 횡단면이었다.** 순위를 매겨 상위 롱·하위 숏.
타이밍 — *언제 들어가고 언제 나오나* — 은 한 번도 안 했다.

외부 실증이 바로 이 형태다: `OctopusTakopi/crypto-trend-following` 이
788 개 무기한에서 **다속도 EMA CTA 로 순 Sharpe 1.04**(설계기간 0.68 /
검증기간 1.54)를 보고했다. 우리 `ema_multi` 는 그걸 **횡단면으로 옮겼다가
−0.08** 이 나왔는데, 원 형태가 타이밍이라 옮긴 게 잘못이었을 수 있다.

## 대상과 규칙

**BTCUSDT 단일 자산**, 전 구간(2020-01~2026-08).
`None`=유지 / `0`=현금 / 양수=롱. 숏은 안 쓴다(타이밍 신호는 대개 롱/현금이다).

| slug | 규칙 | 노출 |
|---|---|---|
| `tsmom_90` | 90 일 수익 > 0 이면 롱 | 1.0 |
| `tsmom_180` | 180 일 수익 > 0 이면 롱 | 1.0 |
| `sma_50_200` | 50 일선 > 200 일선이면 롱 | 1.0 |
| `donchian_55` | 55 일 고점 갱신이면 롱, 55 일 저점이면 현금 | 1.0 |
| `ema_cta` | (16,48)·(32,96)·(64,192) EMA 차를 변동성 정규화 후 `tanh` 평균 | −1~1 을 0~1 로 절단 |
| `vol_target_20` | 항상 롱, 노출 = 20% / 직전 60 일 실현변동성 (최대 3 배) | 가변 |
| `dd_derisk` | 60 일 고점 대비 −20% 밑이면 현금 | 1.0 |

**벤치는 같은 자산 매수보유**다. 횡단면 때와 달리 이건 **베타 착시가 정면으로
걸리는 형태**라 관문 ④(벤치 대비 여유 +0.20)가 특히 중요하다.

## 미리 선언하는 것

**1. 7 건 전부 기록한다.** 123 → 130. 바닥이 또 오른다.

**2. 파라미터는 전부 표준값이다.** 90·180·50/200·55·(16,48)/(32,96)/(64,192)·
20%·−20%. 결과 보고 안 바꾼다.

**3. 알트로 확장하지 않는다.** BTC 하나로 끝낸다. 심볼을 늘리면 심볼당 시행이 되고
수백 건이 된다.

**4. 레버리지를 최적화하지 않는다.** `vol_target_20` 의 20% 와 3 배 상한은 표준값이다.

## 예상

**7 개 중 관문 통과 0 건. 최고 Sharpe 0.9 ~ 1.2.**

근거:

1. BTC 매수보유가 Sharpe 0.90 · 연 43% 인 강세장 표본이다.
   **롱/현금 타이밍은 강세장에서 매수보유를 이기기 어렵다** — 빠진 날이 손해다
2. 앞선 프로젝트에서 *"노출·구성을 바꾸는 판단은 다섯 번 전부 비용이었다"*
3. 외부 저장소의 1.04 도 **268 개 시장 분산**과 **위험균등 배분**에서 나온 것이지
   단일 자산 타이밍이 아니다

**구체적으로: `vol_target_20` 이 최고일 것**으로 본다. 변동성 목표는 수익을
거의 안 건드리고 변동성만 낮추므로 Sharpe 가 기계적으로 오른다.
**그게 엣지인지 회계인지는 별개**이고, 낙폭이 같이 줄면 진짜에 가깝다.

## 반증 조건

- 하나라도 바닥을 넘고 관문 통과 → 배터리
- `vol_target_20` 만 통과하면 → **엣지가 아니라 위험 회계다.**
  같은 변동성으로 맞춘 매수보유와 다시 비교해야 한다
- 전부 벤치 미달이면 → **타이밍 축도 없다.** 후향 탐색 종료
